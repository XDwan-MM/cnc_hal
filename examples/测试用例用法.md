# 四轴台架联调程序

这是可执行的上机测试代码，不连接机床。当前台架从站顺序按现场提供的信息预填：0=IO 面板，1=IO 模块，2=主轴伺服，3～5=三台进给伺服。主轴在 HAL 配置中放入 spindles[0]，逻辑轴号 0；进给轴逻辑号为 1～3。源码位于 hal_hardware_test.c，现场参数在 hal_hardware_test_config.c；程序只通过 include/hal_c_api.h 调用 HAL。

## 编译

~~~bash
cmake -S . -B /tmp/hal-hardware-test-build -DHAL_BUILD_HARDWARE_TEST=ON -DBUILD_TESTING=OFF
cmake --build /tmp/hal-hardware-test-build --target hal_hardware_test
/tmp/hal-hardware-test-build/hal_hardware_test selftest
~~~

从构建树运行需要先指定设备字典（安装后的库会使用其安装路径）：

~~~bash
export CNC_HAL_DEVICES_JSON="$(pwd)/src/Greemaster/devices.json"
~~~

selftest 只做静态配置反例检查，不打开主站。输出中的 EXPECTED_REJECT 是故意提交错误配置并确认 HAL 拒绝；最终出现 PASS 且进程返回 0 才是测试通过。

## 现场必须填的参数

编辑 examples/hal_hardware_test_config.c：

1. 主站 cycle_us、start_timeout_ms、cycle_timeout_ms、dc_enable。
2. 四台驱动逐台填写 estop_action、编码器类型、反馈每转脉冲数、命令/反馈当量、方向、enc_off。当前代码中 1.0 当量只是**计数单位占位值**，绝不能据此放行运动。进给轴核实后分别将 settings->feed[i].scaling_confirmed 置 1；主轴还要确认角度当量、速度 PDO 的单位确为 rpm（不是 0.1 rpm，HAL 现在按 1:1 处理）、max_speed、speed_window，再设置主轴的两个 confirmed 标志。
3. 以驱动铭牌/EEPROM 核对四台的 vendor/product/revision 能被 src/Greemaster/devices.json 识别。只有“标准 PDO”不足以确认型号匹配。
4. 面板/IO 的各 Entry 位宽、按钮/端子与 X/Y 字节位映射。预填的 X/Y 段是面板 0～255、IO 256～511；该空间足够单模块每方向最多 64 个 32 位 Entry，但**具体哪一位是什么信号仍需现场摸点**。inputs 命令可逐点记录变化。
5. 所有信息审核后，才把配置函数最后的 return -1 改成 return 0。若仍有非法参数，hal_config_validate 会拒绝运行。

## 执行顺序

~~~bash
TEST=/tmp/hal-hardware-test-build/hal_hardware_test
$TEST selftest
$TEST static
$TEST observe
$TEST protocol         # 周期调用顺序与未使能运动门控
$TEST inputs           # 每次改变一个面板按钮或 IO 输入点；记录 X 差异
$TEST io               # 填满 y_safe/y_test，且 io_images_confirmed=1 后才运行
$TEST axis 1
$TEST axis 2
$TEST axis 3
$TEST estop 1          # 静止使能后测试配置的 DS402 急停，可换 1..3
$TEST calibrate 1      # 独立机械基准已确认时运行，可换 1..3
$TEST offset 1         # 验证 enc_off 改变后的启动坐标差，可换 1..3
$TEST spindle-estop    # 主轴静止使能后检查配置的急停动作
$TEST spindle-speed    # 主轴 CSV 低速正转，到位后写 0 并检查停转
$TEST spindle-reverse  # 主轴 CSV 低速反转，到位后写 0 并检查停转
$TEST spindle-angle    # 主轴 CSP 小角度位置运动
$TEST stop             # request_stop 与周期线程 join 的交接
~~~

axis 用例每台都要求 scaling_confirmed=1、有限目标、正的 max_step、允许误差和 settle_cycles；使能前、使能后各检查一次目标差不超过 max_step，运行中持续读取反馈，结束时调用该轴软件急停。它只发一次位置目标，**不是限速轨迹生成器**。请先在驱动器中设好速度/转矩限幅、独立实体停止手段，并将目标设置为现场批准的微小位移。spindle-speed/reverse 会先确认零速，再分别试一个方向并停止，不在旋转中直接反向；spindle-angle 先将静止的当前位置临时定义为本次测试的 0°，再把 [-360°,360°] 的配置角度作为相对零点的刻度下发：正数正转到该刻度，负数反转到该刻度，±360° 分别完整转一圈。它在同一周期内先暂存命令，再读取轴状态中的 command_pos 和 actual_pos，以两者之差检查 max_angle_step；超限则在 commit 前调用急停取消暂存位置，超限目标不会写入目标位置 PDO。两个主轴运动用例都要求已核对命令/反馈当量。

IO 输出用例只有在两幅完整 Y 映像逐位审核后才允许调用，且需要操作员输入 YES。y_safe 是全部输出点的安全状态，y_test 应先复制 y_safe，再只改变批准测试的位；两者都是完整映像，不是只包含一个输出点的稀疏列表。零字节也可能意味着某些输出有效，因此不能默认“全零即安全”。未填写 IO 位映射时先运行 inputs/observe，不运行 io。所有用例打印 API 返回码、轴身份、位置、状态字和故障码；现场原始 PDO 与实际端子/电机动作仍应同步记录。程序未在本环境中连接硬件，上述步骤的真实结果待现场执行。

主轴伺服虽与进给伺服硬件相似，CSV 转速与 CSP 角度仍是不同 HAL 路径，需分别跑上述用例。编码器当量、速度 PDO 单位和 IO 位映射目前尚未取得，相关运动/输出命令会保持锁定。

## P1 能力查询

`hal_context_start()` 成功后，可以按扫描顺序调用 `hal_slave_count()`、`hal_slave_info()` 查看每台物理从站，含未识别的从站。轴功能按逻辑轴号调用 `hal_axis_capability()`；从站级报警控制按从站位置调用 `hal_slave_capability()`。例如：

~~~c
HalCCapability cap;
if (hal_axis_capability(ctx, axis_id, HAL_FUNC_ERROR_CODE, &cap) == HAL_OK &&
    cap.state == HAL_CAP_UNSUPPORTED) {
    /* cap.reason 描述未绑定的功能；轴的其它功能可继续使用。 */
}
if (hal_slave_capability(ctx, slave_pos, HAL_FUNC_ALARM_CONTROL, &cap) == HAL_OK &&
    cap.state != HAL_CAP_READY) {
    /* 该从站目前不允许调用报警控制。 */
}
~~~

P1 依据当前已装配的 PDO 句柄评估位置、速度和故障码；缺少 0x603F 时 `HalCAxisStatus.error_code_valid` 为 0。主轴速度是必需功能，缺少相关 PDO 会阻止启动。报警控制尚无设备规则和调用实现，因此保持 `HAL_CAP_NOT_CONFIGURED`，不会向从站写 0x6FFF。ESI 描述与新增 PDO 映射分别在 P2、P3 接入。
