# 2026-10-01 版本范围与验收

- 制定日期：2026-09-27
- 当前主分支：`master`，沿用现有 EEPROM / 默认 PDO 启动路径
- ESI 解析、索引、离线审核及后续适配：保存在 `codex/esi-adaptation`，不进入本版
- 本版目标：以现有设备与已运行过的上机用例为基础，整理构建、回归、现场结果与版本说明，形成可交付的一版

## 截至 9 月 27 日的已知状态

现有 C HAL 支持主站启动、已有设备字典匹配、PDO 句柄装配、DS402 位置/速度接口、IO/面板读写接口、按从站/轴查询基本能力。模拟 SDK 回归覆盖配置、context、驱动、字典与 DS402。用户确认 `examples` 中的上机用例已经测试；本次分支整理尚未收集对应的设备、SDK/FPGA 版本、输出日志与通过/失败明细，因此不替这些试验判定结果。

台架测试程序的拓扑按现场提供的顺序预填：0 面板、1 IO、2 主轴、3～5 三台进给伺服。原测试配置及其 `confirmed` 标志保持原样。本次分支拆分没有改动运动、输出参数或测试门控。

## 本版验收顺序

1. **构建与离线回归。** 在目标 Linux/SDK 环境构建共享库和 `hal_hardware_test`；运行 `python3 -B test/run_driver_tests.py`、公开 ABI 链接检查及 `hal_hardware_test selftest`。本次已用 GCC 直接链接 SDK 1.1.8，库、上机程序、`selftest` 和 `static` 均通过；当前环境尚无 CMake，CMake 构建/安装检查待补。
2. **整理已有实测。** 将已运行的 [上机用例](../examples/测试用例用法.md) 按命令列出结果，记录设备身份、SDK/FPGA 版本、PDO 映射、参数取值、日志及异常。已有记录可直接复用，不机械重复整套测试。
3. **补缺与回归。** 只针对缺少记录、失败项及本次主分支改动做必要复核；重点看正常启动、停止、再次启动、通信异常及配置失败后的状态。
4. **形成版本。** 核对共享库及上机程序能在目标环境构建，写明已通过的现场范围和仍有限制；打版本标签和发布动作以最终验收结果为准。
