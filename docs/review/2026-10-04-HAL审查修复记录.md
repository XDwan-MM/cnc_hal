## 2. 问题、修复和证据

### HAL-01：上使能执行遗留的位置目标

- 原因：`SwitchedOn` 且模式正确的分支直接写 `0x0F`，未预置当前位置；去使能只取消 HAL 暂存目标，驱动器里的旧目标还在。
- 原始复现：实际计数 `100`、遗留目标 `9000`，使能后控制字为 `15`，目标仍为 `9000`。
- 修复：`src/common/Ds402.h` 的 `DS402_STEP_ENABLE_OP` 也设置 `preset_target`。驱动层保持“先预置目标、成功后才写控制字”的顺序；HAL 原有命令/反馈当量不同的覆盖换算仍生效。
- 回归：`test/context_regression.c::review_regressions` 验证初始 SwitchedOn、发送位置目标后去使能再重使能，两种路径都先把目标恢复为实际计数 `100`；`test/ds402_test.c` 校验预置标志；`test/driver_regression.c::servo_tests` 验证位置写入先于 `0x6040`，位置写失败不会继续使能。

### HAL-02：历史停止覆盖故障复位

- 原因：`stop_override` 跨周期保留，commit 把 begin 准备的 `0x80` 覆盖成 `0x07` 或 `0x00`。
- 原始复现：急停后注入 Fault，再请求复位，最终状态为 `HAL_RESET_TIMEOUT`；发送控制字为 `7`，Fault 仍在。
- 修复：记录显式停止所在周期。停止与复位发生在同拍时，停止优先，复位返回 `HAL_ERROR_STATE`；后续拍受理显式复位会清除历史停止动作覆盖（`stop_override=0`）。一次停止请求不是永久闩锁。复位始终不请求使能。
- 停止打断进行中的复位时取消请求，状态变为 `HAL_RESET_NONE`，并由 commit 覆盖当前拍的复位控制字。`NONE` 只表示无复位请求，不表示成功。上层有持续急停输入时，应持续调用停止接口，不能只依赖历史一次请求。
- 回归：`review_regressions` 覆盖去使能、去使能急停、撤销电压急停后的后续复位；覆盖两个调用顺序下的同拍冲突；覆盖 begin 已写高电平后、commit 前被停止打断；取消后下一拍仍发送停止控制字。复位 PENDING 时使能被拒绝。

### HAL-03：Fault Reset 缺少完整上升沿和释放

- 原因：每拍写同一 `0x80` 不是新上升沿；DONE/TIMEOUT 后 DS402 的 DISABLE 分支可能不写控制字，bit7 残留为 1。
- 原始复现：在只接受 bit7 上升沿的模拟器中，第一次返回 DONE，第二次返回 TIMEOUT，控制字仍为 `128`。
- 修复：运行层产生 `0x0000 → 0x0080 → 0x0000 → 0x0080 …`。采到非 Fault 或超时后再发送 `0x0000` 释放 bit7。纯函数只描述单次高电平动作，连续复位脉冲由运行层管理。
- 回归：模拟器在 commit 时检测完整 bit7 上升沿；普通 `0/7/15` 不再错误地解除 Fault。连续两次故障都能各收到新上升沿；忽略第一次上升沿后，第二个上升沿能恢复；成功和超时后都检查 bit7 为 0。
- 限制：模拟验证的是控制字序列；实际驱动器所需脉宽、重试间隔和故障清除条件仍须现场确认。

### HAL-04：CSV 忽略方向参数

- 原因：位置使用 command/feedback invert，速度直接写 `rpm × dir`、直接读有符号原始值。
- 原始复现：两个 invert 都为 1，目标与读回速度仍为 `+100`。
- 修复：写 PDO 时使用 `round(rpm × dir × command_sign)`；读反馈使用 `signed32(raw) × feedback_sign`。对外的 command_speed、actual_speed 和 at_speed 使用调用方坐标系；位置当量不参与速度比例换算。
- 回归：`review_regressions` 覆盖 command/feedback invert 的四种组合，以及正转和反转命令，分别核对两字段的符号换算。原始速度固定为 `+100`，模拟器不随命令产生物理反馈，包含方向不一致的合成输入；`at_speed == !feedback` 只验证调用方坐标系下的比较，不能证明任意配置组合在实机上有效。
- 限制：速度对象单位仍假设为整数 rpm；单位比例尚不能配置。接口文档旧的“计数/秒”和“乘除 6”说明已更正，不代表速度单位已获硬件确认。

### HAL-05：停止未启动实例影响主站持有者

- 原因：`hal_context_request_stop` 无条件调用全局 `Master_RequestStop`。
- 原始复现：A 已启动、B 只创建，对 B 停止后，A 的 wait 返回 `11`（STOPPED）。
- 修复：每个 context 仍记录自身停止通知；只有 `owner == c` 时才通知驱动层。
- 回归：创建 A/B，启动 A，停止并销毁 B，验证驱动停止位不变，A 正常完成周期。原有并发停止回归继续验证对持有者的通知能穿透到驱动层。生命周期仍须按公共契约串行处理。

### HAL-06：主站周期/DC 开关没有传到从站映射

- 原因：从站映射固定 `sync0_cycle=1000000 ns`、shift 为半毫秒、activate 为 `0x300`。
- 原始复现：主站周期 `2000 us`，从站仍是 `1000000 ns`；DC 关闭时 activate 仍为 `0x300`。
- 修复：主站配置传入 EEPROM/映射装配函数；DC 开启时 SYNC0 使用 `cycle_us × 1000 ns`，保留半周期相移 `cycle_us × 500 ns`；关闭时 activate、周期和相移为 0。SYNC1 周期/相移字段保持 0，activate 仍沿用旧值 `0x300`，不能据此认定 SYNC1 已关闭。删除旧的写死周期宏。
- 增加边界：公共配置和驱动配置都拒绝 `cycle_us > UINT32_MAX / 1000`，避免纳秒字段溢出；允许区间为 `250..4294967 us`，这只是表示范围，不代表 SDK/设备支持所有周期。
- 回归：`driver_regression.c::dc_config_tests` 对 `250/1000/1500/2000 us` 分别覆盖 DC 开/关，核对主站实际收到的周期、从站 activate、周期和相移；超大值在任何 SDK 调用前被拒。配置回归也验证上限及上限内的合法值。
- 限制：`0x300` 与 SYNC1 周期/相移为 0 的组合是原有行为，不是本次回归。是否应改为只启用 SYNC0 的 `0x100`，须核对 SDK/设备手册并上机确认，本次保留掩码。不新增逐设备 DC 能力识别，混合不支持 DC 的面板/IO 仍须现场确认。

### HAL-07：复位未发送即超时、周期数向下取整

- 原因：请求在 begin 后受理，下一拍推进前已检查到截止周期；周期数使用整除。
- 原始复现：1 ms 周期、1 ms 超时，进入 TIMEOUT，控制字一直为 `255`，没有发送复位命令。
- 修复：先发低电平准备拍，首次高电平所在拍开始计时；预算为 `ceil(timeout_ms × 1000 / cycle_us)`。成功优先于超时判定。热路径不取系统时钟。
- 回归：1 ms/1 ms 配置至少送出一个上升沿，下一拍才判超时并清 bit7；1.5 ms 周期、2 ms 预算按两拍取整，第一次高电平之后下一拍仍为 PENDING，再下一拍 TIMEOUT。
- 限制：这是配置周期数预算，业务停顿时不保证墙钟时间。调用方反复请求会刷新预算与低电平准备过程，不能每拍重复调用代替查询状态。

### HAL-08：复位缺少运行状态检查

- 原因：复位只检查 phase，没有走统一 gate。
- 原始复现：begin 后 request_stop，再请求复位返回 `0`，而应返回 STOPPED。
- 修复：先检查参数、运行状态、停止通知、总线闭锁，再检查写入窗口。
- 回归：`review_regressions` 验证停止后返回 STOPPED、提交失败闭锁后返回 BUS。原有阶段外拒绝和参数测试继续执行。

## 3. 时序和兼容性

正常清错示例（请求在第 N 拍 begin 后受理）：

| 周期 | begin 准备的控制字 | commit 后的含义 |
|---|---|---|
| N | 保留该拍既有状态推进结果 | 复位请求仅暂存 |
| N+1 | `0x0000` | 确保 bit7 低电平 |
| N+2 | `0x0080` | 首次上升沿，超时起点 |
| N+3 | `0x0000` | 若已解除故障则 DONE；否则释放后等待/重试 |
| N+4 | `0x0080` 或 `0x0000` | 未超时继续重试；超时则释放并返回 TIMEOUT |

begin 中的写入只修改 SDK PDO 缓冲，commit 成功才发送；总线写失败仍闭锁为 BUS，停止通知仍阻止继续提交，不承诺失联硬件执行了停止或复位。

公共 C 结构布局、函数签名、已有错误码和状态常量数值不变，ABI 保持 5.0。本次修复实现既有“取消旧运动、急停优先、复位不使能、方向配置生效”的约束，并明确原先缺少的取消状态解释。`HAL_RESET_NONE` 在停止取消场景下不得当成 DONE；同拍冲突会返回已有的 STATE。内部 EEPROM 装配函数新增周期/DC 参数，使用内部驱动头的桩或工具应重新编译。

`cnc_rt` 仍持有旧静态库，本次没有同步或修改它。后续接入应显式指定新目录：

```bash
cd /home/mxh/CNC/cnc_rt
bash lib/cnc_hal/sync.sh /home/mxh/CNC/cnc_hal
# 然后重新构建 RT 两种模式并运行配置/端到端离线验证。
```

同步脚本的提交号只说明源码 HEAD，不能证明未提交修复已经被记录；本次工作尚未提交时，应同时核对本文、源码 diff 和实际静态库校验和。
