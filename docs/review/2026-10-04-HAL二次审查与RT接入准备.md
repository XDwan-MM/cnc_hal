## HAL-09：OperationEnabled 状态掩码过严（P1）

- 原代码：`DS402_SW_MASK_OP_ENABLED=0x027F`、值 `0x0237`，额外要求 bit4 电压有效与 bit9 Remote 为 1。合法状态字 `0x0027/0x0037/0x0227` 会被误判为未使能；对应的去使能与切模式路径也不会执行应有的 `0x07` 动作。
- 依据：[Synapticon 状态字文档](https://doc.synapticon.com/node/system_integration/status_and_controlword.html) 的 State coding 和 [厂商解码实现](https://motion-master.synapticon.com/docs/cia402_8h_source.html) 使用 `0x006F/0x0027`。bit4/bit9 不参与状态编码；bit5 区分 QuickStopActive，必须保留。
- 修复：`src/common/Ds402.h` 改为 `0x006F/0x0027`，同步注释。运行层采样和驱动层推进使用同一常量，原来 `0x0237` 仍被识别。
- 修前证据：新增 DS402 的三项穷举断言全部失败；驱动层 `Master_ServoStep(0, DISABLE, ...)` 在状态字 `0x0027` 下没有写控制字，新增断言失败。
- 修后回归：`test/ds402_test.c` 遍历全部 65,536 个状态字，分别验证使能事实、去使能与切模式前去使能；`test/context_regression.c::standard_enabled_status` 验证四种 bit4/bit9 组合下的轴/主轴状态及位置/速度命令受理，并拒绝 QuickStopActive；`test/driver_regression.c::servo_tests` 核查实际 PDO 写入。

## HAL-10：撤销电压急停被普通去使能降级（P1）

- 触发：轴配置撤销电压急停，`estop()` 之后调用 `enable(0)`。旧实现无条件把 `stop_override` 改为去使能，并在 commit 写 `0x07`，重新置位控制字的 enable-voltage 位。轴虽不会因此直接 OperationEnabled，但撤销电压的停止动作已被削弱；同拍和后续拍都可触发。
- 修前证据：`test/context_regression.c::voltage_stop_priority` 在“急停 → 去使能”顺序下，commit 后控制字应为 0 的断言失败（实际为 7）。
- 修复：`src/internal/hal_context.c::hal_rt_axis_enable` 在已有撤销电压覆盖时保留 `DROP_VOLTAGE` 请求及覆盖；普通 `on=0` 不降级。显式 `on=1` 或后续拍受理的故障复位仍可解除历史覆盖，同拍停止仍优先。
- 回归：测试两个调用顺序、连续三拍重复 `enable(0)` 后仍保持 `0x0000/0x0040`，再显式使能后正常恢复。首轮的撤销电压急停后复位、同拍停止/复位冲突回归继续通过。
- 契约：公共接口文档及 `include/hal_rt_api.h` 已明确此优先级，不改变结构布局、函数签名、已有错误码及 ABI 5.0。

另修正 `include/hal_control_api.h` 中映像尺寸查询的旧注释：未启动返回 `HAL_ERROR_NOT_RUNNING`、出参不改，实际不会成功返回零尺寸。仅修正文案，与既有实现和回归断言对齐。

## 正式运动接入前仍需处理的 RT 项

> 注：本节与上表记录的是当轮状态。同日第 6 批已删除未构建的 C++ 接口层
> （`IDevice` / `DeviceBase` / `ConfigModel` / `IDIO` 等），因此上表的
> 「DeviceBase」一行与开头「内部 C++ 接口不是当前 CMake 库的运行实现」一句
> 都成为历史。

这些是 RT 业务/适配层问题，本轮只核对并记录，不借 HAL 修复替上层决定机床策略。

| 项目 | 代码依据与后续动作 |
|---|---|
| 使能请求入口缺失 | `src/hal/rt_hal_adapter.h/.c` 只有位置/速度/模式/急停/复位请求，无使能请求；全 RT 没有调用 `hal_rt_axis_enable()` 或 `hal_rt_spindle_enable()`。需把业务使能意图交给唯一 PDO 线程，停止优先，复位后显式重新使能，并轮询真实使能状态。 |
| 运动闸门没有解除流程 | `rt_hal_config.c::recompute_todo` 始终置 IO_MAP/MOTION，两位没有现场确认入口；`motion_allowed()` 持续为 0。需设计可查的现场确认状态，不能直接删位或默认开放运动。 |
| 负当量无法装载 | `main.cpp::fill_hal_params` 直接传 `pm_munit/pm_pulse`，同时设置 invert；配置层要求当量正值。需传正的幅值，把方向保留在 invert，并验证两个方向的命令与反馈。 |
| 急停的持续条件与遗留请求 | `take_requests` 消费一次 `s_req_estop` 后清位，而 HAL 后续受理复位会清历史覆盖；位置/速度/模式 dirty 也未在急停/复位分支丢弃。需维持持续急停条件、解除前禁止复位/使能，并明确丢弃旧运动请求，恢复后重新发目标。 |
| 读取/写入错误不能静默 | `publish_snapshot` 先 memset，再在读取失败时 continue，实际会发布零值，与“保留上一拍”注释不符；普通运动写入返回码被 `(void)` 忽略。需逐轴有效标志及明确的失败处理，不能把无效反馈当原点。 |
| 正常关闭被报报警 | `threads_controller.cpp::pdo_thread_func` 将任何非零 rc 上报；候选正常 SIGINT 退出日志出现 `HAL_ERROR_STOPPED(11) → 报警122`。需区分正常停止和真实故障。 |
| 发布来源与设备字典 | 原 sync 脚本默认指向旧 `../HAL`，只记录 HEAD，不记录 dirty/哈希，且不带设备字典。实际接入须显式指定 `../cnc_hal` 并补来源核查；真实主站启动前须安装字典或设置明确的 `CNC_HAL_DEVICES_JSON` 路径。 |

原适配层的跨线程请求/快照同步还需要在增加使能链时一起核对；本轮验证未覆盖长期并发压力、实际运动或失联硬件的停止效果。

建议顺序：先在 RT 应用已验证的模拟兼容补丁；再实现并测试使能、持续急停/复位互斥与旧请求丢弃；处理参数方向、有效反馈/错误返回和正常退出分类；完成现场台账后才考虑开放运动。DC `0x300/0x100`、SYNC1 零周期语义、速度单位及实际急停/预置效果继续列为上机项。

## 可重跑命令

从 HAL 根目录执行；候选目录须选一个尚不存在的新路径：

```bash
./build_all.sh
ctest --test-dir build/all --output-on-failure -V
python3 test/prepare_rt_candidate.py --rt-root ../cnc_rt \
  --output-dir build/review/rt-candidate-next \
  --rt-patch docs/review/2026-10-04-rt-sim-compat.patch
RT_CANDIDATE_DIR="$PWD/build/review/rt-candidate-next"
mkdir -p "$RT_CANDIDATE_DIR/build/debug" "$RT_CANDIDATE_DIR/build/release"
(cd "$RT_CANDIDATE_DIR/build/debug" && qmake ../../CNC_RT.pro CONFIG+=debug_mode && make -j2)
(cd "$RT_CANDIDATE_DIR/build/release" && qmake ../../CNC_RT.pro CONFIG+=release_platform && make -j2)
(cd "$RT_CANDIDATE_DIR" && bash test/build_hal_config_check.sh)
gcc -std=gnu11 -O1 -g -Wall -Wextra -Werror \
  -fsanitize=address,undefined -fno-sanitize-recover=all -fno-pie -no-pie \
  -DRT_SIM_SOURCE="\"$RT_CANDIDATE_DIR/src/hal/rt_hal_sim_backend.c\"" \
  -I"$RT_CANDIDATE_DIR/lib/cnc_hal/internal" \
  test/rt_sim_candidate_regression.c -o build/review/rt-sim-candidate-check
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 build/review/rt-sim-candidate-check
# 只运行调试版；共享内存库要求 root。三种场景必须串行，使用固定共享内存/临时日志。
sudo bash "$RT_CANDIDATE_DIR/test/rt_offline_smoke.sh" 3
sudo bash "$RT_CANDIDATE_DIR/test/rt_offline_smoke.sh" 5 fault
sudo bash "$RT_CANDIDATE_DIR/test/rt_offline_smoke.sh" 3 busfail
```

共享内存 smoke 前须确认没有正在运行的 RT/HMI 会被测试握手端干扰。本次开始前没有运行中的 RT/握手端。每次 smoke 的 `/tmp/rt.out` 和 `/tmp/hs.log` 会覆盖，重跑者应逐次保留日志。
