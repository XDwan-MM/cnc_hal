# HAL + RT 接入 阅读路线图

**目标**：12 小时内，把「HAL 全部 + RT 我们改动的全部代码」读到**能讲清、能自己改**。

**起手先做一件事**：扫一遍 `port_work/HANDOFF.md`（约 300 行）。它是索引，能省你两个小时。

**跳过**：`HAL/src/Greemaster/` 是你自己写的，不读（只要记得 `Master_ServoRead` /
`Master_ServoWrite` / `Master_ServoStep` 三个入口）。

**配套**：`docs/代码导读.html`（13 节，讲结构：谁调用谁 / 四个公共头 / 三个结构体 /
一个周期三拍 / DS402 / 单位换算 / RT 线程拓扑 …）。
**那份负责"结构是什么"，这份负责"按什么顺序读完"。** 建议第 1 段之前先扫它一遍。

---

## 总览：三层 + 一条数据流

```
        RT 业务（spl_control / emcmot / alarm / jog …）       ← 策略：什么时候动、往哪动
                 │ 只调 rt_hal_*
        RT 接入层（src/hal/rt_hal_adapter.c）                  ← 唯一碰 HalContext 的地方
                 │ 按拍缓冲 + 快照
        HAL（include/ 契约 · hal_context.c 周期 · devdict.c 设备映射）
                 │
        Greemaster 主站（你写的，跳过）
```

**一句话总纲**：
> HAL 是把「一根 DS402 轴 / 一段 IO」变成 C 接口的会话层 ——
> **契约在 `include/`，周期在 `hal_context.c` 的 526 / 590 / 693 三个函数，
> 设备映射在 `devdict.c`，其余全是薄封装。**
> RT 那边只有 `rt_hal_adapter.c` 的四个函数是真东西，其余是接线。

## 第 2 段（3.0h）周期与会话：`hal_context.c` 1067 行 + `Ds402.h` 174 行

### (a) `src/common/Ds402.h` 全读

`Ds402_NextStepReq()`（84 行起）是一张步进表：给「状态字 + 当前模式 + 请求」，
返回「下一步控制字 + 模式」。读懂了它，`hal_context.c` 里的状态机就只剩调度。

### (b) `hal_context.c` 辅助层 101-268

- `report` / `gate` / `bus_error` 101-127
- `signed32` / `command_scale` / `feedback_scale` / `to_counts` 129-151 ← **当量换算，坐标从这来**
- `identity_hash` 153
- `bind_axis` 166-201、`bind_io` 203、`overlap` 231
- `reset_runtime` 237-267 ← **偏置在这里落**（`feedback_offset = -enc_off`）

### (c) 三个周期函数 + 采样 —— 全篇核心

| 函数 | 行 | 干什么 |
|---|---|---|
| `hal_rt_wait_cycle` | 526 | 等到下一拍 |
| `sample_axis` | 539-588 | **PDO 原始值怎么变成 `actual_pos`** |
| `hal_rt_begin_cycle` | 590-691 | 状态机推进、`motion_ready`、刻度基准 |
| `hal_rt_commit_cycle` | 693-730 | **唯一的 bus 发送点** |
| `cancel_motion` | 732 | 取消未提交的运动 |

### (d) 对外接口 269-1067 —— **扫读**

逻辑都在 (b)(c) 里，这里只是形参校验 + 转发。

- 生命周期：`create` 269、`start` 287、`request_stop` 396、`stop` 404、`destroy` 414
- 查询：420-524
- 进给轴：742-869
- 主轴：871-1037（定向 955-983、**单圈刻度 1004-1037**）
- IO：1039-1067

**读完应能回答**
